# Sādhana — practice tracker

A premium, minimalist, dark/light **sadhanā tracker**: take vows (*saṅkalpa*), keep them on a
calendar, and write your way through them in a diary that grows into a personal knowledge base.

The full product thinking is in **[PRODUCT.md](PRODUCT.md)**. This file is about running it.

---

## What's in the repo

```
app/          Interactive app — React + TypeScript + Vite, phone-shaped, runs in the browser
android/      The native Android app — Kotlin, Jetpack Compose, Room, AlarmManager
PRODUCT.md    Refined product definition, spec, design language, roadmap
```

### `app/` — the working prototype (start here)

This is the complete product, running. Every screen, sheet and interaction in the spec is
implemented and driven by real state: marking practices, counts, the four calendar views, streaks,
creating/pausing/stopping vows, the markdown diary with wiki-links and the graph, insights, and
light/dark. Data persists in `localStorage`; a lived-in demo dataset is generated on first launch.

```bash
cd app
npm install
npm run dev      # http://localhost:5173
npm run build    # production bundle
```

On a phone-sized viewport it is full-bleed; on desktop it renders inside a device frame.

### `android/` — the native app

A real Android project (not a mock-up): Room schema and DAOs, the occurrence engine shared by
calendar/streak/alarms, an approximate pañcāṅga, exact-alarm reminders with snooze and "mark kept"
notification actions, tiered on-device AI, and Compose screens mirroring the prototype.

```bash
# Easiest: open android/ in Android Studio (it generates the Gradle wrapper
# jar on first sync) and press Run. Requires JDK 17 + Android SDK 35.
#
# From a terminal with Gradle 8.9+ installed:
cd android && gradle assembleDebug
```

`minSdk 26`, `targetSdk 35`. The wrapper *properties* are committed at
`gradle/wrapper/gradle-wrapper.properties`; the wrapper JAR itself is generated by
Studio/`gradle wrapper` and is intentionally not in the repo.

> **Status, stated plainly:** this environment has no JDK, Android SDK or `dl.google.com` access, so
> the Kotlin module has *not* been compiled here — treat it as a reviewed, complete foundation that
> needs a real Gradle run, not as a verified APK. The `app/` prototype is fully built, type-checked
> and smoke-tested (it renders and every tab works under jsdom with zero console errors).

## How your brief maps to the build

| What you asked for | Where it is |
|---|---|
| Track multiple sādhanās in one place | **Sankalp** tab — any number of active vows, each with its own colour/glyph |
| Track and update them in the calendar | **Calendar** — Day / Week / Month / Year, mark kept in place |
| Optionally add time | Per-vow window: none, a start time, or a start–end range |
| Personal diary, note-taking, Obsidian-ish | **Diary** — markdown, `[[wiki links]]`, `#tags`, backlinks, **Constellation** graph |
| On-device AI, only where the device can run it | Three tiers: Gemini Nano / AICore → MediaPipe lite model → local statistics. **No screen is locked** behind hardware |
| Start from a saṅkalpa day, plan N days | Start date + 21 / 40 / 108 / 365 / custom end / ongoing |
| Optional time or time range + frequency | Daily · specific weekdays · monthly · yearly · **by tithi** · one-off |
| Special anuṣṭhāna on a particular day or tithi | Category `Anuṣṭhāna` + tithi rhythm + one-off dated observance |
| Notification, e.g. 1 hr before, with snooze | Per-vow lead time (at start → 2 hr) and snooze length; quiet hours |
| Stop a vow when done | Detail sheet: **Complete**, **Pause**, **Stop** — history is always kept |
| Come back and mark the day | One tap on Today, or from any calendar view, or a notification action |
| Home: analytics + sankalp status + calendar with views | **Today** (streak, 7-day rate, vows in force, week bars) + **Calendar** + **Insights** |
| Dark **and** light, premium minimalist | Paper / Night palettes, Fraunces + Inter, spring motion, film grain |

## Notes & limits

- **Tithi is approximate** (±~20 min of a real tithi boundary) because it is computed from the moon's
  elongation with low-precision lunar theory. The UI says so. A production build needs a full
  ephemeris and sunrise — see PRODUCT.md §7.2.
- **Notifications in the browser prototype** use the Notification API when permission is granted;
  the in-app reminder card, snooze and quiet hours always work. Exact scheduling lives in the native
  build (`AlarmManager`).
- **No account, no network calls.** Anywhere. Export is a JSON file.
